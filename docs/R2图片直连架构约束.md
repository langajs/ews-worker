# R2 图片直连架构约束

> 生效日期：2026-07-17

## 项目树职责

```text
ews-frontend
  -> 调用 Worker API 获取任务数据、R2 key 和公开 URL
  -> 通过 https://oss.langaj.cc/{key} 预览、打包和导出图片

ews-worker
  -> 处理鉴权、任务数据、上传票据、回调校验和 R2 对象管理
  -> 不代理浏览器读取图片

ews-image-service
  -> Fastify 接收图片任务，BullMQ/Valkey 持久化并削峰
  -> Sharp Worker 下载、转码后通过一次性 PUT ticket 直传 R2
  -> 只向 Worker callback 提交 R2 key 和校验元数据

Cloudflare R2
  -> 通过自定义公开域名 https://oss.langaj.cc 提供图片内容
```

## 硬性约束

1. Worker 不提供 `GET /r2/*` 或其他图片读取代理端点。
2. API 只返回图片对象的 `key` 和公开 URL，不返回由 Worker 中转的图片地址。
3. 前端预览、打包下载和导出字段必须使用 R2 公开域名。
4. R2 公开域名必须允许前端站点执行跨域 `GET` 和 `HEAD` 请求。
5. AI 生成图片不得把图片字节流经过 Worker；唯一例外是浏览器的 `sku-upload` 自上传成品图，Worker 使用内置 WASM 转为 quality 88 JPEG，超过 2MB 时只做一次 Bilinear 等比缩小，然后通过 R2 binding 写入。
6. 外部图片服务不得持有长期 R2 凭据，只能使用 Worker 签发的单对象 presigned PUT URL。

## 自上传 SKU 图片例外

- 仅 `folder=sku-upload` 进入 Worker 图片处理，输入只接受 JPG/PNG，输出固定为 `image/jpeg`。
- `reference`、`auxiliary`、`sku-reference` 等参考素材保持原始字节、MIME 和扩展名，不转码、不压缩。
- 转码后上限为 2,000,000 bytes；超过上限时以 triangle filter（Bilinear）等比缩小一次，第二次编码仍超限则拒绝上传。
- 上传、任务更新和导出均校验任务所有权；普通用户不能通过其他用户的 `task_id` 读写对象或任务数据。

## 变更记录

- 2026-07-17：移除旧 `GET /r2/*` 路由及前端兼容转换，统一为 R2 公网直连。
- 2026-07-18：图片处理拆分为 Fastify API、BullMQ/Valkey 队列和 Sharp Worker，服务异步直传 R2 并回调对象 key。
